
  1. Product Contract
  Based on repo evidence, NewsCraft is a local FastAPI/PostgreSQL ingestion and review system with a Next.js
  operations dashboard.

  Backend: backend/app/main.py:10 starts FastAPI, CORS, /health, and routes. backend/app/api/routes.py:33
  exposes sources, source seed/detail, dashboard summary, ingest run trigger/list, media assets, content item
  list/detail/approval, and diagnostics.

  Ingestion/jobs: backend/app/worker.py:10 runs IngestionService and optional media downloads. backend/app/
  daily_bundle/__main__.py:91 runs existing RSS/Telegram ingestion plus GDELT, Google News RSS, Hacker News,
  article extraction, DB persistence, media download, and bundle export.

  Database/storage: SQLAlchemy async models in backend/app/db/models.py:23 define sources, ingest runs, raw
  payloads, content items, identities, media assets, rewrite candidates, and drafts. Alembic migrations are
  active because Compose runs alembic upgrade head before API startup.

  Frontend: Next app routes /, /sources, /runs, /content, /media, /diagnostics mount dashboard components.
  frontend/lib/api-client.ts:15 defaults to /api/backend; frontend/app/api/backend/[...path]/route.ts:41
  proxies requests to the backend.

  Runtime: docker-compose.yml:1 defines postgres, api, frontend, and worker. API/worker use
  newscraft-postgres, media volume /data/media, and proxy defaults pointed at http://xray-proxy:10808.

  User-facing flows: seed sources, run ingestion, inspect source health/detail, review runs, review/filter/
  approve content items, inspect media, run diagnostics, and export daily bundles.

  4. Redundancy Map

  - Historical docs/artifacts: ROADMAP.md, summery.md, media-asset.md, old docs/superpowers/plans/*, tracked
    report. Keep README.md, docs/ingestion-backend.md, docs/proxy-validation-notes.md, and source catalog.
    These are current operator/runtime docs.

  - Content intelligence: classify_content_item() + score_content_item() should survive as source of truth.
    classify_and_score() should be merged down to tag/category helpers or removed after tests prove tags/API
    behavior unchanged.

  - Frontend mock/runtime data: real backend API should survive. dashboardMock should become test/story
    fallback only, or normal runtime should show loading/empty/error states.

  - Source health semantics: backend has healthy/degraded/broken/disabled/unknown; frontend compresses to
    healthy/partial/failed. Backend contract should survive; frontend mapping should explicitly map all
    backend statuses.

  - Frontend page wiring: runIngest mutation logic repeats in dashboard, sources, runs. Keep duplication
    unless touching behavior; hook extraction is optional, not deletion-first.

  - UI primitives: active primitives survive: badge/button/card/progress/separator/table/tooltip. Unused stock
    primitives can be deleted if this repo is not preserving a shadcn component library surface.
